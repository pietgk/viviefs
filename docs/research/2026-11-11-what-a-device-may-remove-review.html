Round 5 of the log-store guide, 2026-11-11

Lesson 3: what a device may remove

You found lesson 3 confusing: device-a reading "this device's" log, trace/motel appearing from nowhere, and arrows that point the wrong way. You asked whether we had gone down a rabbit hole or made a design error.

It is a design error. The lesson describes compaction as it was designed on 2026-09-20. Later decisions changed who reads a device's log, and compaction was never updated to match. Half of this was already reported as finding A01 Compaction and rebuild do not compose safely; the lesson exposed the other half.

Where device-a came from

ADR-0011 Log store pattern, read models, compaction and analytics (2026-09-20) says "compaction only past a horizon every device has acknowledged". That assumes a log many devices read from, compacted once every device has pulled it. Since then D119 Time corrected by authority and P11 Identity decided that the server's log, the only log devices read from, is never compacted. And no device ever reads another device's log. The table name device_cursors and the suite's device-a are left over from the old design. P10 Trace projection then added trace sinks to the same table, which is why the lesson had both.

2. Reproduced on the real code today

One SQLite device and one trace sink, with the real createList, LogStore and Projector. This was a throwaway test, now deleted, so it is not qualification evidence.

1. The read models miss facts

The projector never saw the list. Its place is not counted.

2. A rebuild empties them (A01)

Project first, then compact, then rebuild(). The sync client calls rebuild() when the server rejects a changeset.

before: ['Visit']

The read models are "disposable", but nothing is left to rebuild them from.

3. With no reader, nothing goes

No consumer registered.

removed 0, horizon 0,
heldBy null

This part holds: no registered reader ever misses a fact.

3. What a correct rule needs

A device may remove a fact only when all three of these hold:

  1. Every reader on the device has processed it, the projector included. The log store can check this.
  2. The server holds it: the device pulled it, or the server accepted it. Only sync knows this.
  3. A rebuild can get it back, from the server or from a snapshot. Only sync, or a snapshot design, can do this.

Conditions 2 and 3 depend on the server, and the server belongs to sync, a later pattern. The log store comes first, so it cannot check them (D82 Patterns build on each other). That is the real design error: compaction was placed in the log-store pattern, but whether it is safe can only be known one pattern later.

4. Options

A. The log store teaches what it delivers now; device compaction moves to sync (recommended)

Lesson 3 becomes "Each reader keeps its own place". It covers streamFrom(cursor) and the acknowledged cursor, with the two real readers on a device: the read models and trace export. The mistake to try is to save the place before delivering. After a crash in between, the reader skips facts for good. Delivering first means a crash only causes a resend, and the store ignores a resent fact by its tx. Lesson 1 already taught that.

sequenceDiagram
  participant L as Device log
  participant T as Trace export
  participant M as motel (the sink)
  T->>L: streamFrom(its place)
  L-->>T: the facts after it
  T->>M: send the spans
  M-->>T: received
  T->>L: acknowledge(trace/motel, last seq)
  • A new issue, "Device compaction", records the three conditions and the reproductions. It is decided with the sync pattern, which can check conditions 2 and 3.
  • ADR-0011 is amended: the log-store pattern does not deliver device compaction. The server's log is still never compacted.
  • The conformance suite and exercise 03.01 stop using device-a. The exercise becomes "deliver, then acknowledge" for a trace sink. The glossary's Consumer entry loses device-a.

B. Make compaction correct now

Register the projector as a consumer, compact only what the server holds, and have a rebuild on a compacted device pull again from the server. This builds sync knowledge into the log store, or a sync check into it. P04, P05 and P09 would all re-run, and snapshot versus re-pull would have to be decided now, before any app needs compaction.

C. Fix only the words

Replace device-a with the projector and a sink, and have the lesson name the two open gaps. The lesson would still teach an incomplete rule as the rule.
