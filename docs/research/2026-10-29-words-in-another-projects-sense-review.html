2. The mark

D198's defaults: a block quote, and one explicit mark around a passage or table in another project's words, switch off glossary links and ids inside them. Here is the form I recommend, worked on I25's archify table:

Source (.md)

archify's diagram kinds, as its README lists them:

<!-- their words: archify -->

| Kind | What it draws |
| --- | --- |
| architecture | boxes and arrows |
| workflow | steps of a process |
| sequence | messages over time |

<!-- /their words -->

Our Workflow is durable work on the workflow engine.

In a guide (.mdx) the same pair is written as JSX comments, {/* their words: archify */} and {/* /their words */}. That follows the References: marker, which already has both forms. The pair also works inside one sentence or one table cell, around a phrase.

A. The form the _Avoid_ line writes (recommended)

A retired word whose _Avoid_ entry is in code font fails verify in code font, outside a mark: today only node. Code font was the only way the old sense was written (D103's stopgap), so a match is drift every time. A retired word in plain text is not checked, for the same reason D180 gave for not failing _Avoid_ words: they are everyday words, wrong in only one sense. The rule is read from the glossary, so a later retirement in code font is checked without code changes. Recorded as D180'.

B. Every retired word, as D180 says

About 230 uses fail now. Almost all are correct, so they would have to be reworded or marked. Marking them would wrap our own plain English ("deferred to map 4") in a "their words" mark, which turns the mark into a way to switch off the check. It also contradicts D199, which already said bare node and bare surface are never checked.

C. A phrase list per word

Each _Avoid_ line would name the phrases our old sense used ("the engine", "deferreds"). Tried on today's text: about 30 matches, and most of them are still other senses ("the worker's onerror", Effect's "the engine re-runs"). The list would be hand-kept, it would catch little, and it would need marks again.
