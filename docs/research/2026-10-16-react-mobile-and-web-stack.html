React for mobile and web: Expo or One, and what goes around it

An earlier conclusion picked Expo with Unistyles 3. One is now a serious candidate. This page compares the two for a TypeScript and Effect codebase, covering the app, the UI layer and the backend, including Hono and Alchemy (I28). Every claim is sourced in the record.

Verdict: keep Expo + Unistyles 3. Watch One and probe it later.

  1. RN version gap. One 2.7.7 peers react-native ^0.87.0, which excludes 0.88. Expo SDK 58 and this repo are on 0.88.
  2. Too new, one maintainer. One's v2 has been stable for 3 days, and one person wrote about 89% of the commits among its top six contributors.
  3. Expo's web gap has closed. SDK 58 made SSR, data loaders and middleware stable. One's FAQ line "Expo Router is SPA-only on web" is out of date.
  4. One's data story doesn't apply here. One recommends Zero, but ViViEfs already has its own datom sync. What One adds for us is Vite everywhere and inline Swift/Kotlin. Both are real, but neither justifies requalifying P01 now.

Pros and cons

One

For

  • One bundler (Vite 8, Rolldown) for native and web, matching our tests and docs.
  • No Metro, so no babel stub for Effect's Migrator dynamic import.
  • getRandomValues, randomUUID and subtle.digest installed on Hermes at startup.
  • Per-route SSG, SSR and SPA; Hono server included; deploys to Node, Vercel and Cloudflare.
  • Swift and Kotlin imported straight from TypeScript, plus full SwiftUI and Compose.
  • Same SQLite driver we already use (op-sqlite 18.2.5).

Against

  • RN 0.87 only; we are on 0.88.
  • Stable v2 is days old; navigation sits on alphas; five patch releases in 48 hours.
  • One main author.
  • Unistyles under its no-Babel pipeline is unverified; Uniwind is Metro-only.
  • Our dev-client and @expo/agent-cli path would need rework.
  • Its comparison with Expo is out of date, so check every comparison it makes.

Expo

For

  • Already qualified here (P01, ADR-0004).
  • SDK 58 web: stable SSR, loaders, middleware, API routes; adapters for Node, Bun, Express, Vercel, Netlify and Cloudflare Workers.
  • Largest module set, config plugins, EAS Build, Update and Hosting.
  • @expo/ui for SwiftUI and Compose when we want native controls.
  • Unistyles 3 documents Expo Router.

Against

  • Metro is a second bundler next to Vite; the Migrator stub stays.
  • Render mode is global, not per route.
  • Per-request SSR with Unistyles is unverified (documented: Next.js SSR and Expo static).

UI layer

Unistyles 3 stays the best fit if the design system is styles over plain React Native views. That keeps the view tree unchanged and suits ADR-0019's pure views. Tamagui 3 only wins if you want a component kit and you go with One.

Backend: the fetch handler is the common ground, not Hono

Effect's HttpRouter.toWebHandler turns an app Layer into (Request) => Promise<Response>. Every host below accepts that function, so the backend stays plain Effect and the choice of host can be made later.

Hono

Effect already has its own router and RPC, so Hono only matters as a host, for example inside one serve. Effect's docs show the pattern with ManagedRuntime.

Alchemy

It does not use Hono: the word appears nowhere in its docs. Its APIs are Effect RPC and Effect HttpApi. It has no Expo or One resource; a web build would go through StaticSite or a container. It's still beta, so decide at I7 (I28).

Sync server

It holds leases and a cursor stream open, so it needs a long-lived process: a container or VM (Fly, Hetzner, ECS), not Lambda or a Worker. The web app's server can run somewhere else.

What switching to One would cost here

Small

  • 7 imports from expo* packages in source, each with a One Native equivalent.
  • The evidence app has no router or UI kit yet.
  • The Effect libs and op-sqlite move over unchanged.

Large

  • P01 requalified: RN 0.88 down to 0.87, Rolldown, new polyfill source, new bundle baseline.
  • P01 probe and the @expo/agent-cli device path reworked.
  • ADR-0004 amended.
When to look at One again: it supports the RN version that the then-current Expo SDK ships; v2 goes about three months without breaking changes; a second regular maintainer appears or a company backs it; and a P01-style probe passes under Rolldown (Effect 4, op-sqlite, the datom store, the workflow check, Unistyles through a Babel transform or Tamagui 3).
