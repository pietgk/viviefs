## Notes

- **Superseded, yet alive.** RELEVANCE marks vivief ADR 0047 Superseded, but its datom shape, provenance as transaction datoms, conflict table and Loro scoping carry forward unchanged into the Active vivief ADR 0051 (0050 and 0051, "What Carries Forward Unchanged"). 09-sources cites the superseded vivief ADR 0047 for `:contract/conflict`; the same idea now stands in vivief ADR 0051 §9. Of vivief ADR 0048 and 0049, React, XState, Ark UI, CSS Modules, WCAG 2.2 AA, model-based testing and Tauri live on in 0051; Deno, Holepunch, Pear, TanStack DB, DuckDB on the server and the Node application server do not.
- **Where the two stacks meet and part.** At the datom level they mostly meet: an append-only `[e, a, v, tx, op]` log, EAVT and AEVT, references sent to a person instead of LWW, DuckDB only for analytics, text settled before it becomes a datom. Below and above it they part: vivief's accepted stack is peer-to-peer typed nodes with convergence, in-memory D2TS indexes rehydrated from a relay's WAL and a web-only UI; ViViEfs is client and server with server authority, a durable SQLite log store on every replica and an Expo app that is native first.
- **The tech-stack chain.** vivief ADR 0046 to 0051 are six ADRs in about three months, each correcting the one before; vivief ADR 0050's Context names the cause itself (`technology choices driven by cascading constraints rather than a coherent vision`). Their spikes were listed but never recorded as runs (`vivief:spikes-required`); ViViEfs runs each spike as a gate before an ADR is Qualified (D46).
- **Agents.** The DevAC ADRs carry most of vivief's working practice for agents: hooks that inject state (0043), one place for what needs attention (0017, 0018), a benchmark that measures whether a tool helps an agent (0022), stable element refs (0035). ViViEfs has only the last; the others are `missing` rows for map 6.
- **Index drift in vivief.** README and RELEVANCE omit vivief ADR 0052 and still list 0040 as Accepted and Active; RELEVANCE's Summary undercounts Transitional by one; vivief ADR 0014's Status date precedes its ADR date. vivief ADR headings with an em dash are cited here without it.
- **Reused ids.** Six I35 ids are refined here (`vivief:provenance`, `vivief:schema-contract`, `vivief:render-contract`, `vivief:aggregation-rule`, `vivief:convention-over-configuration`, `vivief:content-addressed-cache`) and four I36 ids get their vivief side (`viviefs:analytics-as-projection`, `viviefs:one-datom-log`, `viviefs:adr-lifecycle`, `viviefs:browser-engine-leader`); I45 merges them with the index rows. Where this file's status for a reused id differs from I35 (`viviefs:adr-lifecycle` is `different` here, I35's `vivief:adr` is `taken`), the difference is the lifecycle detail the ADRs add.
