## Notes

- **Where the two stacks meet and part.** They meet on the practice of checking: every automated check passes or fails (`Binary eval or nothing`, `taken`), text settles before it becomes a fact (`taken`), non-goals are declared, a spike states its pass and fail thresholds, and the step from issue to accepted work is guarded by status checks that `verify` runs. They part on three things. First, in the intents vivief puts models inside the running system: a router model picks the handler, Code Mode runs model-written TypeScript in a sandbox, query templates and skills accumulate as data, prompts tune themselves overnight, an ATLAS pipeline repairs; ViViEfs makes no model calls at run time and keeps agents as developers of the repository, so these 14 rows are `missing` and feed map 6. Second, vivief keeps its own evidence and an agent's memory as datoms (`This is non-negotiable`), where ViViEfs keeps evidence out of the log on purpose (D48', `rejected`) and memory in files (issues, handover).
