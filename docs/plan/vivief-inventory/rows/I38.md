## Notes

- **Where the two stacks meet and part.** They meet where ViViEfs already works by vivief's rules without its words: summaries before full content (taken), every claim cited back to its source, a person deciding every convention change, outside skills reviewed before they land, samples that cannot drift, a span-derived state diagram checked against the run. They part on three things. First, vivief routes an intent to whichever handler fits (by role, trust, confidence, aperture); ViViEfs wires one named command per intent and makes a missing Layer a compile error. Second, vivief makes trust a number that flows (`min()`, no automatic rise, sandboxes per level, detection Guards, a threat model); ViViEfs has server authority and Schema at every boundary and nothing for outside content or agents. Third, vivief's improvement starts itself (aggregation triggers, a Researcher then an Improver, proposals as datoms); ViViEfs improves when a person runs `retro` or a grilling. Those rows feed map 6, which takes 24 of the 42 reference-stack rows. Map 5 gets the UI and docs rows (machines and stories as documentation, coverage by state, static accessibility, a queryable docs graph, docs freshness); map 2 the bridge, intake, domains and the fractal-factory framing; map 4 the docs lifecycle and the creation loop.
