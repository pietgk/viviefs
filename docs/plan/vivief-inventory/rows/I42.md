## Notes

- **Where the two stacks meet and part.** They meet where DevAC's ideas are general and ViViEfs already has them in its own form: trace context carried in the envelope (`taken`), one model with implementations behind it (`taken`, though DevAC lacks a shared suite), a single writer with promotion when it dies (`taken`, unverified on both sides), facts kept apart from the meaning derived from them, ids every copy computes alike, and an incremental path that P05 checks against a full rebuild where DevAC states none. They part on the code itself: DevAC turns code into a graph, effects, rules, C4 and dynamic views, queried in SQL by people and agents over MCP, and ViViEfs has none of it (the `missing` rows of map 5 and DevAC tooling, all I25's "Not taken"). On run time they part on where the join happens: vivief would copy test spans into its query store and join them to static effects by entity id, with the OpenTelemetry SDK, where ViViEfs derives durable spans from the log, exports through Effect's own exporter (`rejected` for the SDK) and keeps sinks as viewers; the matching itself was never built in vivief either. On agents they part on how a tool's value is measured: DevAC's eval scores answers with a model as judge, where every ViViEfs check passes or fails. Map 5 takes 12 of the 25 reference-stack rows, map 2 six (ids, the meaning split, queries, the single writer, protocol versions, degradation), map 4 four (writes, incremental checks, budgets, implementations), map 6 two (the eval and its judge), map 3 one (the word "effect").
- **What the fact docs are.** The README says built, yet three files are not: otel is a guide whose exporter does not write and whose checks run `After implementation`, ipc is an analysis of a known bug, rm is a plan. 09-sources points at otel for "Idea: match traces against extracted effects (later)", so the idea ViViEfs picked from vivief is one vivief only planned.
- **Contradictions inside the folder.**
  - *Built or future.* rules, pl and views present the rules engine and C4 views as built (`Part of DevAC v3.0 Foundation`); rm §10 lists `Rules Engine` as phase 10 and observability as phase 8, both future.
