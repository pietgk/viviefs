## Comparison

Type safety: XState and effect-machine keep impossible phases out of the
state tree; Atom uses a tagged `CaptureEvent` union plus a reducer that
refuses illegal transitions. effect-machine keeps Effect errors typed;
XState's `fromPromise` erases them into Promise rejection.

Test and story ergonomics: all three wrap the same `CaptureSession`. Atom
adds the least extra API because query atoms already use `AtomRegistry`.
effect-machine `send` is async enqueue (`runFork`); checks and stories wait
for the snapshot.

Product-specific criteria (voice, affordance) stayed out (D55).
