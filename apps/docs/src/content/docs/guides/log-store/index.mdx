## What it is

Every fact in ViViEfs, from a list title to a workflow's journal entry, is a
datom in one append-only log. This pattern keeps that log: it appends datoms, mints the transaction id that orders them, streams
them from a position, and keeps each reader's place in it. One
`LogStore` service runs over Effect's `SqlClient`, so the same code and the
same suite cover SQLite on iOS, Android, the web and Node, and Postgres on the
server.

Who holds the log, and why the server's copy differs from a device's, is on
[Concepts](/guides/log-store/concepts/#who-holds-the-log) and in the first lesson.

Why one log: [ADR-0006 One datom log as the substrate][ADR-0006]. Why this clock: [ADR-0007 Hybrid logical clock for tx][ADR-0007]. Why
one contract with several stores: [ADR-0011 Log store pattern, read models, compaction and analytics][ADR-0011].

## When to use it

- You are storing a fact: domain data, a journal entry, membership. It goes
  into the log as datoms, and every other table is derived from it or holds
  one replica's own state.
- You need a new place to run: a new SQLite driver, a server database. It is
  a new log store implementation, and it is done when it passes the suite.
- You need to read everything that happened after some point: sync, trace
  export and projections all stream the log from a cursor.

## When not to

- Several facts that must become visible together: that is a changeset, built
  on the log store ([ADR-0008 Single-datom transactions with changesets][ADR-0008]; the changesets guide comes next).
- A query shape for a screen: that is a read model, rebuilt from the log and
  never migrated. You may drop any read model; how one is built belongs to the
  changesets guide.
- Analytics: project to Parquet or DuckLake and query with DuckDB. DuckDB is
  never the durable log ([ADR-0011 Log store pattern, read models, compaction and analytics][ADR-0011]).
- Telemetry storage: traces are derived from the log; a tracing backend is a
  viewer, never a journal ([ADR-0006 One datom log as the substrate][ADR-0006]).

## What it teaches

Never assumed; each word is shown with its glossary entry where it is first
used. What every guide assumes is on [Before you start](/guides/before-you-start/).

- **Lesson 1**: a Datom and its six parts, Entity (`e`), Attribute (`a`), the
  value `v`, `tx`, `op` and the changeset `cs`; the Log store, appending, a
  duplicate, a Log position; who holds the log: a Device, the Server and its
  Authority, Sync node, Consumer.
- **Lesson 2**: the clock that orders facts (HLC), and which of two values counts.
- **Lesson 3**: each reader keeps its own place in the log, and moves it only
  after it has delivered (Consumer, Acknowledged cursor).
- **Lesson 4**: one contract kept by several stores, SQLite and Postgres.
